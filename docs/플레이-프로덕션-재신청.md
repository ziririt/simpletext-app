# 플레이 프로덕션 재신청 — 세 번째 (2026-10-28 작성)

> 두 번 떨어졌다(10-13, 10-28). 이 문서는 세 번째를 떨어지지 않게 하는 계획과 재신청서 초안이다.
> 사람(소유자·테스터)이 할 일과 담당자가 할 일을 갈라 적는다. 진행하면서 이 문서를 고친다.

## 1. 무엇이 떨어졌나 — 판정과 실측

메일(2026-10-28 07:08 KST, 제목 "Google Play 프로덕션에 액세스하려면 추가 테스트 필요")은 앱 이름이
없었다. 콘솔에서 확인했다 — **Skyblue Note 대시보드**에 "오늘, 오전 7:08에 검토되었습니다"가 떠 있다.
이유 둘은 10-13 의 첫 번째와 글자까지 같다.

- 비공개 테스트 중에 테스터가 앱에 참여하지 않았다
- 앱 업데이트를 통해 사용자 의견을 수집하고 조치하는 테스트 권장사항을 따르지 않았다

콘솔에서 잰 것(10-28 12시 무렵):

- 비공개 테스트 트랙 'Alpha' — 활성, 178개 국가, 최신 출시 255(3.19.0, 10-13 게시). 그 전은 254(09-14).
  **테스트 기간 내내 플레이 트랙에 올라간 새 판은 10-13 의 255 하나뿐**이다. 09-19 이후 고침은 대부분
  셔버드 덧판으로만 나갔다 — 덧판은 구글 눈에 '앱 업데이트'로 안 잡힌다
- 테스터 목록 '비공개 테스터 목록' **33명** 연결(다른 목록 'LongLong 내부 QA' 1명은 연결 안 됨)
- 대시보드 조건: 비공개 테스트 게시 ✓, 12명 이상 참여 선택 ✓, "검토일부터 14일 더" 미충족
- **설치한 사용자 수(기기에 앱이 깔린 사람)**: 10-07 ~ 10-26 날마다 12~17명, 대부분 13명. 10-13 에 테스터께
  다시 메일을 보낸 뒤에도 늘지 않았다. 33명 중 실제로 깐 사람은 셋에 하나꼴이다
- **매일 쓰는 비율(DAU/MAU)**: 같은 업종 앱 중앙값이 8~9% 인데, 우리는 10-12 ~ 10-21 열흘 중 **8일이 '-'**
  (잴 만큼 쓴 사람이 없음), 10-13 에 7.14%(약 1명), 10-15 에 42.86%(약 6명 — 다시 보낸 메일 직후 하루)
- 테스터가 플레이 스토어에서 보내는 **비공개 테스트 의견: 0건**. 의견 받는 곳은 이메일 주소 하나로만 걸려 있다

### 왜 '참여 안 함'으로 판정됐나 (분석)

1. **깔기만 하고 안 쓴다.** 참여 선택 33명 → 설치 13명 → 날마다 쓰는 사람 거의 0명. 구글은 '참여 선택'
   숫자가 아니라 실제 사용을 본다. 메일을 보낸 날 하루 반짝하고 다시 0이 된 모양은 "부탁받아 한 번 열어 본"
   것으로 읽힌다.
2. **안드로이드에서 구글 드라이브 동기화가 처음부터 안 됐다.** (10-28 확인) 플레이에서 받은 앱은 구글의
   앱 서명 키로 다시 서명돼 있다(SHA-1 `B4:3E:E8:98:C0:11:AC:B4:8D:4D:CA:A2:73:C4:F2:1E:9B:6F:70:42`).
   구글 클라우드 'Skyblue Note' 프로젝트의 Android 로그인 클라이언트에는 다른 지문
   (`28:61:8B:A7:E5:50:C0:61:D6:47:FD:C8:67:F2:DA:39:6E:78:DC:4D`, 우리 업로드·개발 키 쪽)만 등록돼 있다.
   그래서 플레이로 깐 모든 안드로이드 폰에서 구글 계정을 고르는 마지막 단계가 거절된다(소유자 10-24 신고와
   같은 증상). 노트 앱에서 기기 사이 동기화가 안 되면, 아이폰을 주로 쓰는 테스터는 안드로이드 폰을 다시
   열 이유가 없다 — 참여가 0으로 가라앉은 가장 큰 기술적 원인으로 본다.
3. **업데이트가 한 번뿐이었다.** 고침은 많았지만 플레이 트랙에는 255 한 번. 구글의 둘째 이유가 정확히 이것이다.
4. **의견이 구글 눈에 안 보인다.** 플레이 비공개 의견 0건, 의견은 사적인 메일·말로만 오갔다.
5. (짐작) 33명 중 상당수가 아이폰 사용자일 수 있다. 미국주식 카페 모집글로 Gmail 만 받은 경우, 안드로이드
   폰이 없으면 깔 수가 없다. **소유자 확인 필요.**

## 2. 이번 14일 계획 (2026-10-28 → 11-11)

대시보드 문구 그대로 "검토일부터 12명 이상의 테스터를 대상으로 14일 더". 검토일이 10-28 07:08 이므로
**가장 빨리 다시 낼 수 있는 때는 11-11(수) 07:08 이후**다. 날짜만 채우고 내면 또 떨어진다 — 숫자가 바뀐 것을
콘솔에서 확인한 뒤에 낸다. 한 번 더 떨어지면 다시 14일이다.

목표 숫자(구글이 공개한 기준은 '12명 이상 · 14일'뿐이다. 아래는 그 위에 얹는 안전 여유다):

- 테스터 목록 **25명 이상**, 그중 **안드로이드 폰에 실제로 깐 사람 20명 이상**
- 14일 동안 **매일 쓰는 사람이 있는 날이 대부분**(DAU/MAU 가 '-' 인 날이 없게). 사람마다 매일일 필요는 없고,
  20명이 일주일에 서너 번씩 열면 날마다 몇 명은 쓴다
- 플레이 트랙 **새 판 2회**(256, 257) — 각 판의 출시 노트에 "테스터 의견으로 고친 것"을 적는다
- 플레이 **비공개 테스트 의견 5건 이상**(테스터가 플레이 스토어 앱 화면에서 남기는 것)

날짜표(한국 시각, D0 = 10-28):

- **D0~D1 (10-28~29)** 안드로이드 구글 로그인 고침 — Android 로그인 클라이언트를 하나 더 만들어 플레이 앱 서명
  지문을 등록. 앱은 다시 굽지 않아도 된다(서버 쪽 등록). 소유자 폰에서 동기화가 붙는지 확인
- **D1~D2 (10-29~30)** **256 을 alpha 에**: 안드로이드 동기화 고침 + 그동안 덧판으로만 나간 것(맨 위 표준 배너,
  설정·떠 있는 판에서 배너 걷기, 제미나이 새 이름)을 플레이 판에 싣는다. 테스터 공지 1회차
- **D1~D7** 새 테스터 모집·목록 추가(목록에 넣은 날부터 그 사람의 시계가 돈다 — 늦게 넣을수록 손해). 의견 받기
- **D4 (11-01)** 담당자가 콘솔 숫자 점검(설치·DAU·비공개 의견) → 부족하면 소유자께 바로 알린다. 테스터 공지 2회차
- **D8 (11-05)** **257 을 alpha 에**: D1~D7 에 받은 의견으로 고친 것. 출시 노트에 의견과 고친 것을 짝지어 적는다.
  테스터 공지 3회차("말씀하신 ○○을 고쳤습니다")
- **D11 (11-08)** 담당자 점검 2회차
- **D12 (11-09)** 필요하면 258(작은 고침). 테스터 공지 4회차(마지막 며칠 꾸준히 열어 달라)
- **D14 이후 (11-11 07:08~)** 콘솔에서 숫자 확인 → 기준을 넘었으면 재신청(아래 4절 초안). 못 넘었으면 며칠 더 돌리고 낸다

덧판(셔버드)은 계속 쓸 수 있지만, **구글에 보이는 '업데이트'는 플레이 트랙의 새 판뿐**이다. 테스트 기간에는
의견을 반영한 고침을 덧판이 아니라 새 판으로 낸다.

## 3. 누가 무엇을 하나

### 사람이 직접 해야 하는 일 (담당자가 대신 못 한다)

  - (보충) 개발자끼리 서로 테스트해 주는 모임(테스터 품앗이 카페·오픈채팅 등). 실제로 쓰는 사람이어야 의미가 있다
  - 기존 33명 중 아직 안 깐 20명에게는 "안드로이드 폰이 있는지"부터 묻는다 — 없으면 목록에서 빼도 된다(12명 밑으로만 안 내려가면 된다)

- **테스터께 공지 보내기**(카톡·메일·카페 쪽지). 문구는 담당자가 초안을 쓴다(아래 5절)
- **테스터 본인이 할 일**: 참여 링크 열기 → '테스터 되기' → 플레이에서 설치 → 2주 동안 일주일에 서너 번 이상 열어 쓰기 →
  플레이 스토어의 앱 화면에서 '비공개 의견 보내기'로 한두 줄 남기기
- **재신청서의 사실 확인** — 모집 방법, 모집 난이도, 받은 의견. 소유자만 아는 사실이다
- **구글 클라우드 Android 로그인 클라이언트** — 담당자가 만들어도 되는지 허락(또는 소유자가 직접). 소유자 계정의 설정을 바꾸는 일이라 허락이 먼저다

- D4 · D8 · D11 · D14 에 콘솔 숫자 점검해 보고(설치한 사용자 수, DAU/MAU, 비공개 의견)
- 테스터 공지문 초안, 받은 의견 정리, 재신청서 작성(사실은 소유자 확인 뒤)

## 4. 재신청서 초안 (11-11 이후 제출용)

> `[ ]` 안은 소유자만 아는 사실이거나 테스트가 끝나야 채울 숫자다. **지어 넣지 않는다.**
> 각 칸은 300자 제한. 지난 두 번과 달리 "이번에 달라진 것"이 숫자로 보이게 쓴다.

**1단계 · 비공개 테스트 정보**

- 테스터를 어떻게 모집했나:
  "유료 테스트 업체는 쓰지 않았습니다. 첫 신청 뒤 구글 안내에 따라 모집 방식을 바꿨습니다. 안드로이드 폰을 실제로 쓰는
  가족·지인·회사 동료 [ ]명에게 직접 부탁하고, 활동 중인 투자 커뮤니티에 안드로이드 사용자 대상 모집글을 다시 올려 [ ]명을
  받았습니다. 안드로이드 폰이 없어 설치할 수 없던 초기 신청자는 목록을 정리했습니다. 현재 [ ]명이 참여 중입니다."
- 얼마나 쉽게 모집했나: `[ 어려웠음 / 보통이었음 ]` (소유자 판단)
- 테스터 참여도:
  "테스터 [ ]명이 2주 동안 일상 메모 앱으로 썼습니다. AI 답변 붙여넣기·정리, 노트 작성·편집, AI 편집, 자동 바꾸기 규칙,
  그리고 이번에 고친 구글 드라이브 동기화(안드로이드↔아이폰·웹)를 주로 썼습니다. 실제 사용자도 같은 방식으로 쓸 것으로
  봅니다. 다만 결제·잠금 같은 기능은 일부만 써 봤습니다."
- 받은 의견과 수집 방법:
  "의견은 플레이 비공개 테스트 의견([ ]건), 이메일, 메신저로 받았습니다. 주요 의견: [ 의견1 ], [ 의견2 ], [ 의견3 ]. 첫 신청 때는
  안드로이드에서 구글 드라이브 동기화 로그인이 실패하는 문제가 있었고, 테스터 신고로 원인(앱 서명 지문 미등록)을 찾아 고쳤습니다."

**2단계 · 앱 정보** (지난 신청서 그대로 써도 된다 — 사실이 안 바뀌었다)

- 주요 대상: AI 도구 답변을 자주 복사해 쓰는 일반 사용자(직장인·학생·블로거), 여러 기기에서 같은 노트를 보려는 사람
- 가치: AI 답변의 마크다운 기호·이모지·군더더기를 걷어 깨끗한 글로, 깨진 표 복구, 기기 안 처리, 노트는 본인 드라이브·iCloud 에만
- 첫해 설치 예상: 0~1만

**3단계 · 프로덕션 준비**

- 테스트로 알게 된 것을 바탕으로 무엇을 바꿨나:
  "테스트 기간에 의견을 반영한 업데이트를 두 번 냈습니다. 256([날짜]): 안드로이드 구글 드라이브 동기화 로그인 실패 수정,
  설정·대화상자에서 광고 자리 걷기, 상단 광고를 표준 배너로. 257([날짜]): [ 의견을 반영한 고침 ]. 각 업데이트 출시 노트에
  반영한 의견을 적었습니다."
- 프로덕션 준비를 어떻게 판단했나:
  "iOS 판은 같은 코드로 App Store 에서 서비스 중입니다. 안드로이드는 테스터 [ ]명이 2주 동안 실제로 썼고, 마지막 업데이트
  뒤 [ ]일 동안 새 오류 신고가 없었습니다. 자동 테스트·정적 분석을 통과한 빌드만 올렸습니다."
