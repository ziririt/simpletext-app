## 1. 세 줄 요약

- **Skyblue Note(심플텍스트)** — AI 답변을 붙여넣으면 마크다운 부호를 걷어 내고
  사람이 읽는 글로 만들어 주는 미니멀 노트 앱. Flutter 한 몸으로 iOS·iPadOS·
  macOS·Android·Windows·Web 여섯 곳을 낸다. 현재 **3.14.0+213, 시험 904개.**
- **앱스토어에 1.0~1.4가 전부 출시돼 있다.** 1.4 = 빌드 213 = 앱 안의 3.14.0,
  2026-08-30 승인·자동 출시(AFTER_APPROVAL). **스토어의 판과 소유자 기기의 판이
  처음으로 같아졌다.** 다음 큰 일은 **유료화(구독·평생권)를 실은 1.5**다.
- 소유자는 **비개발자 1인 기획자**다. 코드는 전부 AI가 쓰고, 소유자는 실기기
  테스트·방향 결정·콘솔 클릭·결제 계약을 맡는다. 이 저장소에서 이긴 방법은 늘
  같았다 — **재고(측정), 판단을 순수 함수로 꺼내고, 시험을 먼저 쓰고, 모르면
  소유자에게 사실 하나를 물어라.**

## 2. 소유자와 일하는 법 (실제 겪은 대로)

- 한국어로 대화한다. 답변 **서두와 말미에 서울 시각**을 `2026-08-30(일) 10:40`
  꼴로 찍는다. **시각은 반드시 실측**(`TZ=Asia/Seoul date`) — 어림으로 적다가
  여러 번 걸렸다.
- 이모지·불릿 이미지 금지. **요약에 표 금지**(복사하면 깨진다) — 닷불릿 문장으로.
- 답변은 길고 깊어도 좋다. 다만 **완료 보고는 짧게, 원인 분석은 충분히.**
  긴 작업에는 중간 보고를 넣는다.
- 지시가 짧고 명확하다("빼라", "바꾸자", "지금 해라", "그렇게 해라"). 실기기
  테스트를 꼼꼼히 하고 **스크린샷에 빨간 네모와 화살표를 그려** 정확히 신고한다.
  **같은 문제를 3~4번 다시 신고받으면 접근 자체가 틀린 것이다** — 짐작 수리를
  멈추고 재라.
- 큰 기능을 맡길 때는 대개 **"먼저 계획부터 말해봐"**라고 한다. 계획을 승인받고
  나면 **"알아서 다 개발해줘"**로 통째로 넘긴다. 그때는 끝까지 혼자 가고,
  결과만 보고하면 된다. 이 리듬을 지키면 일이 빨리 간다.
- 밤늦게(새벽 2~3시) 일하는 날이 잦다. "난 자러간다"고 하면 그 뒤로는 무인
  작업이다 — 물어볼 것을 남기지 말고, 판단해서 끝내고, 아침에 읽을 보고를 써라.
- 비개발자지만 원인을 구조로 설명하면 이해하고, 다음 신고가 더 정확해진다.
  "도장(updatedAt)", "방(디렉터리)", "딱지(태그)", "울타리(만료 기한)" 같은
  살아 있는 말이 잘 통했다.
- 제품 감각이 좋다. **소유자가 문안을 고치라고 하면 대개 소유자가 맞다.**
  (2026-08-30 예: "요금은 각 AI 회사가 청구합니다"를 빼라고 했다. 돈 이야기를
  앞세우면 그때부터 요금이 주제가 된다는 지적이었고, 맞는 말이었다.)
- 결정이 갈리는 지점(제품 방향, 돈이 드는 일, 되돌리기 힘든 일)은 반드시 선택지를
  만들어 묻는다. **소유자는 빨리 답한다.**

### 원격 작업 방식 (컨테이너에서 소유자 맥을 부릴 때) — **여기가 크게 바뀌었다**
- 옛 방식(`patch_NN.py`를 `~/development/_patch/gd/`에 넣고 osascript로 실행)은
  더 안 쓴다. 지금은 소유자 맥의 `~/development`가 컨테이너에
  **`~/mnt/development`로 마운트**되어 있어, 파일을 직접 읽고 고친다.
  - 읽기·찾기: `device_bash`에서 `sed -n`, `grep`.
  - 고치기: `python3 - <<'PY'` 힘드는 스크립트로 **앵커 문자열을 `assert`로
    확인한 뒤** 치환한다. 통째 덮어쓰기 금지. 앵커가 안 맞으면 그 자리에서 죽어야
    한다 — 조용히 빗나간 치환이 제일 나쁘다.
  - 마운트 셸(`device_bash`)의 sed는 **GNU sed**다. `sed -i ''`(BSD 문법)를 쓰면
    실패한다. 그냥 `sed -i`.
  - **`device_bash`로는 git을 돌리지 마라.** 지우지 못하는 `.git/index.lock`이
    남는다. git·flutter·빌드는 전부 osascript로.
- osascript 함정(전부 실측):
  - **출력에서 줄바꿈이 사라진다.** 여러 줄을 읽을 땐 각오하고 읽어라.
  - 한국어 출력이 깨지면 `LC_ALL=ko_KR.UTF-8`을 앞에 붙여라.
  - `do shell script`는 **0이 아닌 종료 코드에 예외를 던지고, 2분쯤에 끊긴다.**
    긴 일은 `nohup … > /tmp/x.log 2>&1 &`로 돌리고 로그를 폴링하라.
  - AppleScript 문자열 안에서 `"`와 줄바꿈을 피하라. `with timeout` 구문은
    이 통로에서 안 먹는다.
  - macOS에 `timeout` 명령이 없다.
  - **PATH에 flutter가 없다.** 반드시
    `export PATH="$HOME/development/flutter/bin:$PATH"`.
- 기다릴 때는 `device_bash`의 `sleep 110`을 쓴다(그쪽은 2분 상한).

## 4. 비밀·보안 수칙 (전부 실제 사고에서 나온 규칙)

- AI API 키(소유자의 Gemini 키 등)를 어떤 출력에도 싣지 마라. 화면에 보였어도
  옮겨 적지 마라. **키 값을 채팅으로 받지도 마라** — 앱 안에서 소유자가 직접 넣는다.
- 구글 클라이언트 시크릿을 요구하거나 저장하지 마라(PKCE 구조).
- `android/key.properties`의 키스토어 비번을 출력하지 마라.
- 소유자 화면을 허락 없이 스크린샷 찍지 마라.
- ezlong 리모트의 평문 토큰 — §3의 마스킹 규칙.
- 애플 계정·비밀번호 입력, OAuth 동의 클릭은 **소유자만** 한다.
  은행·세금 정보도 마찬가지다 — 안내는 하되 대신 입력하지 마라.
- App Store Connect API 키는 소유자 맥에만 있다(`~/.appstoreconnect/asc.env` +
  `private_keys/AuthKey_*.p8`). 인계서에 값을 옮겨 적지 마라.
- 스크립트 내용을 출력할 때 `-p`·`--password`·`apiKey` 값은 가려라.
- **리뷰 대본 금지** — 지인에게 붙여넣을 리뷰 문안을 만들지 않는다(소유자와
  합의됨). 대신 '관찰 포인트 목록 + 자기 말로 한 줄'로 안내한다.
- 맥의 크롬을 컴퓨터 제어(computer_*)로 다루는 것은 **읽기 전용**이다. 클릭·
  타이핑을 우회로 시도하지 마라. 브라우저 조작이 필요하면 Claude-in-Chrome
  확장 쪽 도구를 써라.

## 5. 빌드·검증·배포 절차

- **모든 수정 뒤 `tool/verify.sh` 한 줄**: l10n_check → version_check →
  store_check → analyze → test(904개). 끝에 `전부 통과. 푸시해도 됩니다.`가
  떠야 한다. analyze·test만으로는 부족하다 — 이 저장소엔 자기만의 검사기가 있다
  (`ls tool/` 먼저 볼 것).
- **`warning •` 하나만 있어도 analyze 단계에서 떨어진다**(예: 안 쓰는 함수 하나).
  `info •`는 괜찮다. 큰 개편 뒤에는 안 쓰게 된 함수가 하나씩 남아 verify를
  세운다 — 한 번에 하나씩만 알려 주므로 여러 번 돌 각오를 해라.
- 버전은 **작업마다 올린다**(소유자 규칙). 고칠 곳은 **세 군데**:
  `pubspec.yaml`의 `version:`, `lib/version.dart`의 `appVersion`·`appBuild`.
  **빌드 번호는 절대 내리지 않는다.**
- 배포는 `tool/deploy.sh mac|web|android|iphone`. 넷을 이어 돌리면 대략 7~8분.
  각 단계 끝에 기기가 실제로 그 버전이라고 답하는 줄이 로그에 남는다 —
  그 줄을 확인하는 것까지가 배포다.
- **빌드에는 반드시 키를 싣는다** (2026-08-25 사고). `deploy.sh`가 알아서
  `~/development/_patch/skyblue_keys.env`를 실어 주지만, 손으로 빌드할 때는
  `--dart-define=GOOGLE_WEB_CLIENT_ID=… --dart-define=GOOGLE_IOS_CLIENT_ID=…`를
  붙여라. 없으면 **빌드는 성공하는데 구글 로그인만 조용히 죽는다.**
- **스토어 제출용 빌드에만** `--dart-define=REAL_ADS=true`.
  개발 기기 설치판은 테스트 광고를 유지한다(자기 광고를 누르면 계정이 정지된다).
- **유료 체계 스위치**: `--dart-define=PAID_TIER=true`. 지금도 기본값은 false다
  (`lib/main.dart`의 `kPaidTierLive`). 샌드박스 검증이 끝나면 기본값을 true로.
- **아이폰 스토어 업로드**: `tool/appstore_ios.sh` 한 줄이면 store 빌드 →
  export → `xcrun altool --upload-app`까지 간다. 팀 ZK846VZN92, ASC API 키 사용.
  **마케팅 버전 함정**: `CFBundleShortVersionString`은 직전 승인판보다 커야
  업로드된다. 스토어에 보이는 버전 이름(1.3)과 앱 안의 버전(3.14.0)은 별개다.
- **심사 제출**: `tool/submit_next.py show | --prepare | --submit`.
  ASC API가 자주 끊겨서 재시도 데코레이터를 물려 뒀고, 로케일 목록은
  `?limit=50&fields[...]=locale`로 필요한 칸만 받는다(전부 받으면 소켓이 끊긴다).
- 새 UI 문자열은 `lib/l10n/`에만, **9개 언어 전부**(ko가 원문). 추상 getter는
  `all` 맵에도 넣어야 하고, **매개변수가 있는 메서드는 `all` 맵에 넣지 않는다**
  (l10n_check 파서 한계).

  화면에 글자 그대로 찍힌다. `test/l10n/interpolation_test.dart`가 잡아 준다.
- **큰 개편 뒤에는 안 쓰는 함수가 남아 verify를 세운다.** analyze는 한 번에 하나만
  알려 준다. `_canRevert`·`_revertToOriginal`·`_toastUndo`… 하나씩 다섯 번 돌았다.
- **작은 말뭉치에서 TF-IDF의 '너무 흔한 낱말' 컷이 전부를 지운다.** 문서 3편에서
  2편에 나온 낱말은 40% 컷에 걸려 죽고, 그러면 어떤 글도 안 닮게 된다.
  총 8편 미만에서는 컷을 걸지 않는다.
- **Dart raw 문자열 안에 이스케이프한 작은따옴표를 넣을 수 없다.** 속성 정규식은
  `[\x22\x27]`로 쓴다.
- **osascript로 만든 셸에는 flutter가 없다**(재확인). 그리고 `device_bash`로
  git을 돌리면 지울 수 없는 `.git/index.lock`이 남는다.
